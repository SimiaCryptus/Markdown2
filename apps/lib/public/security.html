2. Upfront permission whitelisting

Everything stays fail-closed by default, and integrating pages can whitelist trusted origins, split fetch vs. embed permissions, supply keys, or tune actionable console diagnostics in three ways: 

// 1. JavaScript options (mount, marked.parse, marked.use, new Marked)
const view = mount(el, source, {
  baseUrl: location.href,
  permissions: {
    allowOrigins: ['self', 'https://*.example.com'],
    allowFetch: ['https://cdn.example.com'],
    allowEmbed: ['https://www.openstreetmap.org'],
    keys: [{ kind: 'passphrase', value: 'secret' }],
    logLevel: 'warn', // 'warn' (default) | 'debug' | 'silent'
  },
});

// 2. Custom element attributes
<markdown2-view allow-origins="self https://www.openstreetmap.org" log-level="warn">…</markdown2-view>

// 3. Page-level <meta> tag
<meta name="markdown2-permissions" content="allow-origins self https://example.com; allow-embed https://www.openstreetmap.org" />

3. What the library guarantees

  • Escaped output. Raw HTML is never passed through; links are limited to safe schemes.
  • Nothing implicit. No key is used and nothing is fetched or framed without a grant from the user or your app.
  • Per resource. Grants are bound to one resource's payload and never inherited by nested resources.
  • No sniffing. The declared type picks the handler; a server's Content-Type is ignored.
  • Fail closed. Broken, locked or unknown resources show a labelled stub, never their bytes.
  • Inert images. SVG, WaveDrom, Graphviz and MathJax output is drawn through <img>, where scripts never run.
  • Opaque sandboxes. Rich viewers (Mermaid, Graphviz, Tartlet, Plotly, Vega-Lite, X3D, DataCalculator, Monaco) run in sandbox="allow-scripts" frames with no allow-same-origin.
  • Contained styles. Document CSS cannot fetch, and in mount() it is scoped to its own document.
  • Safe saving. A document cannot pick an active file extension without consent.
