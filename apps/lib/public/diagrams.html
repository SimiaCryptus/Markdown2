Diagrams: Mermaid, Graphviz, WaveDrom & SVG

Every diagram runs offline, never evaluates user source as JavaScript, and renders either through an inert <img> or an opaque-origin sandboxed frame. Edit any source on the left.

1. Mermaid diagrams

text/vnd.mermaid ```mermaid securityLevel: 'strict' opaque-origin sandbox

Both fenced ```mermaid blocks and opaque text/vnd.mermaid resources render inside an opaque-origin frame with Mermaid's strict security level. Invalid syntax falls back to the source.

2. Graphviz (WebAssembly)

text/vnd.graphviz ```dot ```graphviz layout="dot|neato|circo|fdp|twopi|..."

Compiled to WebAssembly in an opaque-origin frame, with the resulting SVG displayed through <img> so graph URL and href attributes stay inert. Pick a layout engine below to update the layout attribute live:

layout=

3. WaveDrom timing diagrams & register maps

text/vnd.wavedrom ```wavedrom built-in (sync) JSON5 parsed, never eval'd

WaveDrom is built right into markdown2.js (no sandbox frame needed). WaveJSON is parsed as relaxed JSON5 data — never evaluated as JavaScript — and rendered to SVG via <img>.

Live view

4. Inert SVG images

image/svg+xml built-in (sync) rendered via <img>

SVGs are always rendered through <img src="data:image/svg+xml;base64,..."> and never inlined into the DOM, so embedded <script> or event handlers cannot execute.
